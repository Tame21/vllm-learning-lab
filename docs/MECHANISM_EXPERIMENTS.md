# 机制观察窗实验指南

从左侧原有专题进入，不需要新增入口。所有画面由浏览器里的教学状态机生成，不运行模型。源码基准为官方 vLLM 提交 `84030bbe3d74d99bad477a3d2e37a973ccd8865c`。

## 通用操作

- “播放 / 暂停”“单步”“上一步”和时间轴控制**事件帧**。一个讲解环节可以出现多次，例如每轮 Decode 都会经历前向、采样和输出。
- 点击下方关键环节，跳到本组参数第一次触发它的事件；未触发的环节打开机制说明。右侧“对应源码”跟随当前环节。
- 改参数会暂停并从头推演；无效参数会保留上一次有效状态并显示原因。
- “实验链接”保存参数与事件位置；刷新和重新进入专题也会恢复本机断点。
- 场景按钮累计 170 个，切换时恢复该专题的基线参数并从头回放；之后仍可单独调参。本文保留前 22 个窗口的操作，本轮新增 39 项和原有观察过程深化见 [路线实验指南](ROADMAP_EXPERIMENTS.md)。短 token 历史按 Enter 应用。

## 1. 一个请求的一生

默认输入 6 个示例 token、输出上限 4。先观察“分配”只有虚线位置，进入“前向”才变成已写 KV；“采样”增加一个输出 token，但它的 KV 要等下一轮才能写入。

把“第几枚输出为 EOS”调为 3，再拖到最后：已采样序列包含 EOS，客户端收到 2 个输出，全部 KV 块释放。设为 0 则按长度上限结束。输入 ID 不是真实分词，交付栏不是实际反分词文本。

## 2. Model Runner V1 / V2

保持“完成 B”“加入 D”开启，观察第二轮的 `C → A → D`。MRV2 中 A、C 的持久行保持不变，D 使用 B 释放的行；gather 用行索引产生紧凑输入。关闭 MRV2，持久行按当轮输入顺序重排。

对照表展示 `input_id`、`position` 和 block table；输出按请求身份返回。每请求每轮只计算一个 Decode 位置，块大小固定为 4，不模拟真实设备拷贝或完整 Prefill。MRV1 / MRV2 都属于 V1 引擎。

## 3. 抢占、重算与取消

容量设为 4、取消为 0，点击“观察抢占”“观察重算”：B 的历史 KV 被回收，已生成的 1 个输出保留；恢复时重算 4 个历史位置，再计算新的 Decode 位置。C 后续也可能因资源不足抢占自身。

把取消轮次设为 2，点击“观察取消”：B 进入终态，归还物理块，后续不再被调度。晚于请求完成的取消不会改写已有结果。

本例使用固定 A/B/C 负载，取消在同步轮次边界生效。此前已执行的工作不会被撤销，也不模拟生产引擎在途任务的延迟释放。需要编辑请求长度、到达时机和预算时，使用“连续批处理”中的请求表。

## 4. FCFS 与优先级队列

三个请求同时到达，默认 A=2、B=0、C=1；**数值越小，优先级越高**。容量调至 10，Priority 首运行顺序为 `B → C → A`，FCFS 为 `A → B → C`。

候选顺序不等于立即获准执行。容量调回 4，观察资源不足、等待和抢占。运行中请求先处理，等待请求按策略选择；需要被抢占的也可能是当前运行请求自身。

左侧比较值是当前事件之前已经首次运行的请求，右侧明确标为另一策略**完整回放**的首运行顺序。轮内已经计算的任务受教学模型的同步约束保护；这里没有复现生产调度器的计划撤销和所有优先级边界。

## 5. 进程通信与异步调度

默认 CPU 准备 2 个时隙、GPU 执行 4 个时隙、交付 1 个时隙。三个输入独立的批次，在同步模式下需要 21 个逻辑时隙；允许重叠时为 15 个。

GPU 执行必须等本批准备完成，结果交付必须等 GPU 完成。淡色条表示未来计划，当前工作带边框；下面的等待和已交付队列随时刻变化。

本观察窗解释 CPU / GPU 重叠与完成依赖，不包含真实 IPC、同一请求依赖上个 token 的全部异步处理、CUDA stream 或通信屏障。时隙不可换算为硬件毫秒或真实加速比。

## 6. 滑动窗口与混合 KV

保持窗口 4、块大小 4。当前 query 到位置 4 时，位置 0 已离开读取窗口，但逻辑块 0 的其他位置仍需读取，所以不能整块释放。继续播放，整块离开窗口后才回收，物理块编号可用于后续逻辑块。

Full Attention 保留完整历史；窗口包含当前 query；黄色表示不读取但仍随部分块保留的位置。状态空间层用固定标量 `s ← 0.5s + x` 对照，说明它不等于逐 token 的 K/V 存储。

示例省略前缀缓存命中、投机额外保留、Mamba checkpoint 和缓存组的完整内存规划；标量递推不是实际 Mamba 算子。

## 7. Beam Search 与多样本

将宽度调为 4，单步观察候选树展开、累加 log 概率、排序保留和剪枝。EOS 候选进入完成集合，不再扩展；到长度上限后合并并返回最优结果。

得分与固定源码的长度约定一致：`累计 log 概率 / (前缀长度 + 非 EOS 输出长度)^长度指数`，这里固定前缀长度为 2。改变候选 A 偏好或长度指数，观察最终排序。

下方独立采样使用相同的三词条件分布和固定随机种子，各样本不互相剪枝。教学模型枚举全部 A/B/EOS 候选，省略真实词表、logprobs 候选截断、结构化输出和模型调用；不是完整 Beam 后端。

## 8. 动态草稿长度

默认区间为 `[1,64] → 3`、`[65,128] → 1`、`[129,512] → 0`。初始 batch size 96 时，四轮负载为 96、144、48、1，对应 K 为 1、0、3、3。

每轮先观察批大小，再查闭区间表，最后准备草稿位置。K=0 明确显示普通目标模型解码继续执行，不表示整个请求停止。调整区间和 K 后，草稿数量会随之重新计算；区间上限必须递增。

K 表由用户配置，不是在线自动寻优。这里计数的是草稿位置，不是目标模型全部验证位置、接受率或耗时；真实方法、Runner、Graph 与 DP 限制仍以对应源码和设计文档为准。

## 9. 模型注册与权重加载

先选“两卡切分”，进入“分片装载与后处理”并连续单步：checkpoint 张量先读取，再逐个 rank 装载，最后变为就绪。`q_proj` 沿输出维切分，`o_proj` 沿输入维切分，norm 向量每个 rank 完整复制。矩阵按教学约定 `[输入, 输出]` 展示，与 PyTorch 权重常见的存储方向不同。

比较“四卡 / 单文件”和“单卡 / 多文件”，可分清 checkpoint 文件分片与 TP 切片。示例每个张量只属于一个文件；不下载权重，不实现 QKV 合并、PP、量化后处理或磁盘 IO。计数反映教学张量元素，不表示真实模型占用。

## 10. Logits Processor 与 Gumbel 水印

四个候选 A/B/C/D 的初始分数固定。每轮先读取生成历史，以 `分数 − 频次惩罚 × 已生成频次` 得到处理后分数，D 可屏蔽为 `−∞`。概率柱保持归一化；屏蔽候选不参与选择。

“Gumbel 水印”对照固定源码 `GumbelWatermarker.sample`：`argmax(logits − log(−log U))`。教学随机数由种子和两 token 上下文生成，**不实现 Philox PRF 或真实密钥**。检测页累加 `−log(1−U)`，按 Gamma survival 计算教学 p 值；重复上下文只计一次。普通采样对照按 Softmax 分布抽样，同一教学 detector 继续计分。小样本 p 值可上下波动，不能判定真实文本来源或事实正确性。

## 11. Embedding 与 Pooling

二维隐藏状态逐位置出现后，MEAN 逐行累加再除以有效长度；CLS 取首位置；LAST 取末位置。右侧坐标图显示隐藏点与汇聚 / 输出向量。切换“MEAN 原向量”与“MEAN + 归一化”，检查方向保持、范数从原值变为 1。

汇聚阶段源码随 MEAN / CLS / LAST 切换，归一化阶段定位 embedding head。零向量保持为零。示例不计算真实隐藏状态、分类 head、cross-encoder 或 late interaction；切换方式不表示实际模型能任意更换任务。

## 12. Prompt Embeddings

比较“预计算输入”与“token 查表对照”：前者对应查表次数为 0，后者每行查表一次；两者都需要组织 position ID，执行前向并写入 KV。逐行高亮让输入向量、位置和固定 4 位置 / 块的逻辑地址对齐。

“改变输入向量”只改变预计算向量首维，未计算或声称实际模型输出。hidden_size 和 position 起点仅用于教学，不代表 API 都支持覆盖位置；真实输入需满足模型维度、dtype、模板和多模态拼接规则。

## 13. 休眠、唤醒与权重更新

Level 1 在 CPU 备份权重，再释放 GPU 权重与 KV；Level 2 只保留适用 buffers，丢弃权重和 KV。进入“唤醒与加载”的首事件可以看到“内存已分配，尚未恢复”；Level 2 必须 reload / transfer 后权重才有效。

选择“Level 2 更新权重”，观察版本 v1→v2，然后恢复 KV 容量、清理旧索引并恢复服务。**容量恢复不等于旧 KV 内容恢复**，最终 KV 仍为空。GPU、CPU 为任意教学容量，buffer 固定为 1 单位；不计通信、Graph 或分配器开销。假设暂停边界已排空在途工作。

## 14. 指标与请求时间线

基准场景：单程传输 10ms、排队 40ms、Prefill 60ms、Decode 间隔 20ms、输出 4 个 token。服务端 TTFT=100ms，客户端 TTFT=120ms，服务端 TPOT=20ms，客户端端到端=180ms。

“网络慢于 Decode”展示服务端可在先前输出仍在传输时继续生成；事件按时刻排序。额外停顿只加入第一个 Decode 间隔；TPOT 用 `(末输出−首输出)/(输出数−1)`，不计首 token。“单 token 边界”没有 ITL，TPOT 显示不适用（本版本统计结构记 0）。全部时间人工设定，使用同一教学时钟；真实 wall-clock 与 monotonic 时间不可直接混算，也不能用单请求时间线代替 GPU profile 或整体吞吐。

## 15. CUDA Graph

默认捕获大小为 2、4、6、8，运行 batch=3 匹配 4 并补一个位置。每个大小分别预热 / 捕获 A/B/C 工作；运行时一次 replay 提交仍执行三个 GPU kernel。准备期捕获计数与本次运行计数分开。

“超出捕获范围”以及“关闭 Graph”进入 Eager，展示三次单独提交。“输入地址变化”是本观察窗演示的安全回退：不能用失效捕获地址继续回放，不表示实际 vLLM 能自动修复任意地址替换。真实 Runner 可向稳定缓冲区复制输入；模式、平台和后端还影响匹配。本例不把提交次数换算成实测加速比。

## 16. KV 卸载

“小容量 / CPU 命中”只提供一个 GPU 槽，按 `0→3→1→3→0` 访问块。观察物理槽反复复用，而 `H / group` 缓存键保持不变；CPU→GPU 传输中标为禁止读取，完成事件后才成为有效副本。

“小容量 / 必须重算”让块 3 的 CPU 副本缺失，首次访问重算；下次驱逐时必须先完成 GPU→CPU 备份，再释放槽。“增加 GPU 容量”可让更多块驻留。三层分别采用教学 LRU。选择“三层小容量 / 回载”改变 GPU、CPU、外部容量，观察 CPU 淘汰、外部备份和逐层回载；选择“CPU 淘汰 / 外部关闭”观察缺失重算。目标确认前无效，源副本在搬运期间保留。外部层是缓存契约示例，不代表所有 connector 提供三层组合；未模拟真实多块 Attention、并发请求 pin、多缓存组或带宽收益。

## 17. 编译、IR 与融合

“融合并复用”将二维 RMSNorm → FP8 Quant 子图合成一个教学 kernel；“关闭融合对照”保留两个提交与物化中间张量。三次调用使用同一数学公式，输出相同。“形状变化”让第二次调用增加一行，新增一项教学缓存；第三次恢复原形状并命中旧项。

教学缓存键按确切形状与融合开关构造，不能代表生产动态 shape、编译分段或后端缓存。中间元素与提交计数不是性能实测。RMSNorm 使用单位权重与 epsilon=1e-6，不替代完整模型融合验收。

## 18. KV FP8 量化

逐 token 查看原始 K/V、FP8 字节、恢复值与读取状态。“scale 太小 / 饱和”把 scale 设为 0.002，使范围外元素饱和；“当前张量自动 scale”分别用 K、V 的 `max|x|/448` 选尺度。最后用相同 Q 对原始与恢复后的 KV 做教学 Attention，展示输出误差。

E4M3 包含次正规数、nearest-even 与有限饱和，数值定义对照 [NVIDIA CUTLASS](https://github.com/NVIDIA/cutlass/blob/main/include/cutlass/float8.h)。实现使用 JS 数值；舍入边界允许自动 scale 带来的一个数值误差量级，不冒充 GPU 转换或 FP32 运算。字节数包含 K/V 各一个 FP32 scale，小张量可能不节省容量。自动 scale 不是数据集校准；Q 量化、逐头 scale、Encoder FP8 与 TurboQuant 保留不同路径边界。写缓存阶段定位 FlashAttention 的 scale 参数，不错误跳到 TurboQuant 实现。

## 19. 加载时在线量化

“普通权重”先加载当前层浮点矩阵，再按 per-tensor scale 转换。逐行动画用于观察，生产转换粒度不由本窗口决定。“权重离群值”增加首行幅度，观察共享 scale 如何改变其余元素的误差。“激活幅度变化”只改变本次输入与动态 activation scale，权重编码保持不变。

两个点积结果使用原始值和编码恢复值，未执行真实低精度 GEMM。权重按 `[输出, 输入]` 展示；不模拟 TP 全局 amax、后端打包、meta 加载或内存峰值。真实后端也可能使用 W8A16，不能把加载期权重量化与运行期激活处理等同。

## 20. DBO 双批次重叠

两个 microbatch 各有“准备 → Dispatch → MLP → Combine”依赖。计算、通信各用一个教学资源，允许两类资源重叠，同一类资源不会同时执行两个阶段。时间线以事件推进：Dispatch 未完成时，禁止本批 MLP 消费结果；Combine 未完成时，批次不交付。

“串行执行对照”让 A 全部完成再运行 B；“通信耗时较长”改变资源等待与总时隙。真实 DBO 面向 DP+EP，有全 rank 准入、线程 yield、recv hook 与 CUDA 事件，并包含更复杂的 MLA / shared expert 顺序。本图只是简化 DAG，不复现完整生产调度或预测加速比。

## 21. DP 负载路由

六个新请求逐个按固定版本 `DPLBAsyncMPClient.get_core_engine_for_request` 的分数选择副本：`max(client_count×inflight, waiting+running) + waiting×6×max(0, KV_usage−0.5)`。本例只有一个客户端；最低分并列时从当前起点扫描，下一请求旋转起点。

“空队列 / 同分轮转”展示轮转；“负载感知路由”使 rank 0 有背景积压与较高 KV 压力；“显式指定副本”跳过分数选择。结果始终从选中副本返回原客户端，扣减 in-flight；协调器快照等下一次刷新。背景积压不在六个新请求的执行范围内，不模拟多客户端、特殊 pooling 路由或真实跨 rank 同步。

## 22. Prefill / Decode 分离

P 为请求生成 KV，D 的对应块先保持无效。逐块或分组传输时，进度到达末时隙仍须等完成确认；只有全部所需位置有效后才允许 Decode，并产生一枚标注清楚的占位输出。每块四个位置，末块有效长度单独计数。

“传输失败阻塞”让最后一组失败，保留已确认块，D 不产生输出；不假设所有 connector 都自动重算。“合并四块传输”改变提交次数与教学总时隙，不代表真实网络吞吐。窗口并排显示同一 Prompt 的单实例对照：直接读取本侧 KV，无需跨实例传输，分离侧失败不影响这条独立路径。比较的是逻辑依赖，不是性能。源码用于对照 KVConnector 的读写完成契约；未实现底层传输、元数据协议或真实模型前向。
