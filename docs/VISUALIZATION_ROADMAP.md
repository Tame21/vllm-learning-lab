## 当前覆盖

新增 24 个算法专题和 20 节前置基础后，按 `content.mjs` 注册的 114 个专题、`engine.mjs` 的执行记录入口和 `renderers.mjs` 的实际分发统计：

| 当前形式                | 数量 | 学习者实际能看到什么                                                                   |
| ----------------------- | ---: | -------------------------------------------------------------------------------------- |
| 前置基础数值推演        |   20 | 概率尺、联合表、向量、频率、高斯曲线与生成画布；见 [基础学习指南](FOUNDATIONS.md)      |
| 机制状态推演            |   17 | 请求、输入张量、调度、缓存、候选树、时间线等状态由页面内的教学模型生成，再逐事件呈现   |
| 算法逐步计算            |   24 | 采样、投机、模型数学、缓存、数值与路由的可参数化计算；见 [算法指南](ALGORITHMS.md)     |
| 专用示意图 / 数值小实验 |   11 | 有矩阵、概率柱、设备或传输图；其中采样和量化已有数值计算，但部分专题只有很少的视觉状态 |
| 投机方法图解            |   12 | 按方法展示不同输入、结构和依赖；大部分仍使用固定示例和四个讲解阶段                     |
| 通用流程图              |   30 | 高亮执行节点，切换正文与状态说明；没有该机制专属的数据结构和状态推演                   |

第一轮前 38 / 70（约 54%）使用通用流程图；第一轮后为 30 / 70（约 43%）；新增算法章后为 30 / 94（约 32%），新增前置课后为 30 / 114（约 26%）。这些新增基础课没有替代尚待完善的机制流程。专用图解和方法图不等于都已提供同样深度的交互动画。

初始盘点的结构性原因与本轮改动：

- [`renderers.mjs`](../src/renderers.mjs) 的 `scene()` 对未实现专用场景的专题调用 `flow()`；后者主要显示节点、文字和进度标记。
- [`engine.mjs`](../src/engine.mjs) 的 `buildTrace()` 对未接入教学引擎的专题直接映射 `lesson.steps`，没有独立的运行状态。
- [`app.mjs`](../src/app.mjs) 的播放循环只负责递增帧位置。增加播放速度或 CSS 效果不会自动补出请求、张量、缓存或依赖关系。
- 本轮页面根据实现区分“执行观察窗”“流程概览”“机制图解”，[`learning-view.mjs`](../src/learning-view.mjs) 的徽标同步区分“可推演实验”“流程概览”“专用图解”。

原机制章中仍有的代表性缺口（算法章补充其数学部分，但没有替代完整机制模拟）：CUDA Graph 的四个步骤主要共用“捕获 / 回放”两种图；LoRA 只有适配器区域激活变化；EPLB 共用设备模板，完整机制章尚未呈现专家布局迁移。新增 LoRA / EPLB 算法章已经提供低秩数值计算、负载副本分配和容量装箱。

## 第一轮：已补齐 8 个基础状态观察窗

按以下顺序完成：生命周期 → Runner → 抢占 / 取消 → 优先级 → 异步 → 混合 KV → Beam → 动态 K。统一支持参数重算、回放、事件帧与讲解环节映射、源码跳转及断点恢复。

落地范围：抢占和优先级观察窗使用固定三请求负载，完整请求编辑仍在连续批处理专题；异步提供 CPU / GPU / 结果三泳道，暂不模拟真实 IPC 和同一请求跨轮依赖；混合 KV 的状态空间对照是示例递推，暂不包含 checkpoint。这些扩展仍可继续深入，不应把基础观察窗视为生产实现的完整复现。

下表保留初始建议，作为后续深化的参考。优先级依据是学习主线、明确可观察状态和现有引擎复用；工作量为相对估计，不是工时承诺。

| 顺序 | 专题                 | 建议的观察窗                                                                                  | 学习者可改变的输入                     | 工作量 |
| ---: | -------------------- | --------------------------------------------------------------------------------------------- | -------------------------------------- | ------ |
|    1 | 一个请求的一生       | 同一请求依次进入前端、队列、GPU、采样和流式输出；token 与 KV 块随轮次变化，结束后回收         | prompt 长度、输出上限、停止条件        | 中     |
|    2 | Model Runner V1 / V2 | 请求 A/B/C 的持久行、当轮顺序、gather 索引与 `input_ids` / `positions` / block table 并排变化 | 新增 / 完成请求、本轮请求排序、V1 / V2 | 中     |
|    3 | 抢占、重算与取消     | 显存不足 → 选中受害请求 → 释放可释放块 → 重算 KV → 继续生成；取消走独立终止路径               | 块容量、取消时机、请求长度             | 中     |
|    4 | FCFS 与优先级队列    | 同一组请求在两种策略下的候选顺序、资源准入、抢占和完成次序                                    | 到达顺序、优先级、预算                 | 中     |
|    5 | 进程通信与异步调度   | 前端、EngineCore、CPU 准备、GPU 执行泳道；标出完成事件、屏障和批次 N / N+1 的重叠             | 同步 / 异步、示例阶段耗时              | 大     |
|    6 | 滑动窗口与混合 KV    | token 向前推进时，窗口滑动、旧块跳过或释放；完整注意力和不同缓存组并排对照                    | 窗口长度、block 大小、层类型           | 大     |
|    7 | Beam Search 与多样本 | 候选树逐层展开，显示累计分数、保留分支和被剪枝分支；对比独立多样本                            | beam 宽度、候选分数、停止条件          | 中     |
|    8 | 动态草稿长度         | 并发数跨越配置区间时，K 与草稿位置数量同步变化；K=0 展示关闭草稿的路径                        | batch size、区间表                     | 小     |

复用与边界：

- 请求生命周期可组合现有调度、KV 和采样教学组件，不需要运行真实 tokenizer 或模型；示例 token 必须标明是教学输入。
- 抢占已有 [`engines/scheduler.mjs`](../src/engines/scheduler.mjs) 的块释放、历史重算和输出保留逻辑可复用。取消事件、在途资源与优先级还要增加状态，不能只给现有图改标题。
- Runner V2 的持久请求行与当轮 gather 可直接对照固定版本的 `docs/design/model_runner_v2.md`；不能把两个 Runner 的布局画成完全相同。
- 异步调度使用带依赖的教学时间线。只有满足完成条件后才允许消费结果，示例时间不作为硬件实测。
- 混合 KV 需区分 full attention、sliding window 和状态空间缓存；不能把所有层都表示成同一种 K/V token 数组。
- 动态草稿区间来自固定版本的配置规则；文档示例值不表示通用最优参数。

| `scheduler`   | 连续批处理                 | 把每轮的准入、分配、执行、采样、释放拆成可暂停的子帧，保留现有前后状态表 |
| `chunked`     | 分块预填充                 | 同一工作负载的切块 / 不切块对照采用同步时间轴；明确停滞不能当作更快      |
| `paged`       | 分页 KV 缓存               | 逐个 token 展示逻辑块、物理块和 slot 的对应，增加读 / 写地址连线         |
| `prefix`      | 自动前缀缓存               | 显示整块 hash 查找、引用计数变化和未命中尾部；保留末尾 logits 计算边界   |
| `speculative` | 投机解码：猜测与验证       | 把候选位置的接受检验逐项推进，首拒绝后同步显示剩余草稿丢弃和恢复分布     |
| `tp`          | 张量并行 TP                | 局部矩阵计算与归并逐项显示，通信前后数值保持可检查                       |
| `pp`          | 流水线并行 PP              | microbatch 保持稳定身份，突出填充、稳态和排空；动画遵循现有依赖          |
| `moe`         | MoE 与专家并行 EP          | token 从原 rank 到 Top-2 专家再返回，配合路由权重与加权结果              |
| `structured`  | 结构化输出：JSON / Grammar | 高亮当前语法状态、允许集合变化和被排除候选，继续说明示例词表的范围       |

## 实施方式与验收标准

1. **先定义状态，再画动画。** 每个机制输出初态、事件、下一状态与可观察数值；动画、解释、指标和源码入口读取同一份执行记录。
2. **讲解步骤与播放帧分开。** 一个讲解步骤可包含多个微事件帧，通过 `stepIndex` 关联原有讲解、理解题和源码，避免增帧后跳错代码。
3. **复用三类场景。** 请求 / 资源状态用于生命周期、抢占、睡眠和故障；带依赖的时间线用于异步、DBO 和传输；张量 / 表格映射用于 Runner、Pooling、LoRA 和量化。
4. **保持对象身份。** 请求、token、物理块和专家使用稳定标识。现有 [`dom.mjs`](../src/dom.mjs) 已保留部分控件节点，可扩展稳定标识支持，再做位置和数值的过渡动画。
5. **参数必须改变结果。** 改窗口长度应改变可见历史，改优先级应在适用场景改变候选顺序，改 beam 宽度应改变保留分支，不能只修改说明文字。
6. **提供失败或边界场景。** 如没有 KV 空闲块、没有历史匹配、CUDA Graph 形状未命中、传输尚未完成、优先请求仍受资源限制。
7. **改善学习深度提示。** 入口与观察窗使用“可推演实验 / 专用图解 / 流程概览”标识，避免所有专题给人同样的动画深度预期。
8. **保留可控回放。** 暂停、单步、回退、重置与参数复现必须正确；减少动态效果偏好、键盘操作和窄屏均可使用。
9. **验证机制而非截图。** 检查块不重叠、资源守恒、依赖先后、停止后不继续生成、概率归一化等不变量，再验证页面和源码定位。

建议实施顺序：第一轮 8 个流程专题 → 第二轮核心示意图与相关数值实验 → 投机方法的可编辑输入 → 模型/平台特定分支。保留无需 GPU、固定版本源码、离线运行的现有使用方式。
