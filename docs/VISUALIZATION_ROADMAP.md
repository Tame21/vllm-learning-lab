## 2026-10-01：按路线逐项完成

本轮新增 39 个状态观察窗，深化原有 9 个状态专题，并补齐 KV 三层缓存和单实例 / 分离部署逻辑对照。下列“完成”指浏览器教学模型达到本文可观察状态与边界标准，不表示运行真实模型、GPU kernel、网络或外部训练库。逐项操作见 [路线实验指南](ROADMAP_EXPERIMENTS.md)。

### 核心示意图升级

- [x] `prefill`：跟随 Q/K/V 行和缓存增长，确认最后一枚输出的 KV 尚未写入；EOS 后不再前向。
- [x] `sampling`：按 logits → 温度 → Softmax → Top-p → 重归一化 → 指数竞赛回放；T=0 跳过随机分支。
- [x] `quantization`：观察逐元素缩放、舍入、有符号整数和 INT4 字节打包，再从字节恢复数值。
- [x] `cp`：DCP 用局部输出和 LSE 合并；PCP 先分 Q/K/V，再 Gather KV，结果与全量因果 Attention 对照。
- [x] `eplb`：先构建影子布局、迁移所有目标权重，再越过屏障切换映射；旧布局在迁移期间继续有效。
- [x] `lora`：同批 A/B/base 输入逐行绑定适配器，计算 Wx 和 B(Ax)；反转行顺序后请求结果保持一致。
- [x] `multimodal`：分别观察图像行、视频帧与音频特征的占位对应；重复键复用 encoder，数量不符时阻止前向。

### 投机方法可编辑输入

- [x] `ngram`：编辑短历史后按 Enter，观察最长后缀窗口、最早匹配位置、复制范围与共同贪心验证。
- [x] `ngram-gpu`：比较 A/B 的有效长度与 pad=-1；屏蔽 B 后它不产生候选。本窗口只计算 GPU 输入输出契约。
- [x] `suffix`：调整频次门限，观察经验后缀树的条件概率与候选路径停止；未知上下文保持无候选。
- [x] `draft-model`：每个候选成为下一次草稿输入；区分已输入位置的 KV 与尚未输入的最后候选。
- [x] `eagle`：逐步对齐 token、position 和目标特征，再使用教学递推状态生成候选。
- [x] `eagle3`：改变辅助层数，观察同位置多层特征拼接宽度与递推草稿输入。
- [x] `mtp`：对照条件性的 IndexCache 共享与重新计算，不将模型专属模块画成通用 MTP 架构。
- [x] `mlp-spec`：仅演示级联输入依赖，终态明确保持未接入；不追加接受数、bonus 或可执行配置。
- [x] `medusa`：同一隐藏状态扇出到独立预测头，各头并列组成候选，额外骨干前向为零。
- [x] `parallel-draft`：观察 anchor 与 K−1 个 mask 一次进入骨干；关闭训练准备条件后保持阻塞。
- [x] `dflash`：先准备上下文 KV，再组装 anchor+K 个 mask 查询位置，一次骨干输出候选。
- [x] `dspark`：并行骨干后，Markov 偏置逐候选依赖上一个采样结果；切换 anchor 预测布局与偏置。

### 输入、服务与故障协议

- [x] `speech`：音频块抵达、编码、分组提交和文本上下文续接分开，重复提交计数保持一次。
- [x] `tools`：缩小字符块大小，观察不完整标签保留在 parser 缓冲区；合法 JSON 才交付工具对象。
- [x] `thinking`：零预算和多 token 结束标记按顺序强制；交错段分别重置计数，正文不扣思考预算。
- [x] `encoder-disagg`：媒体特征完成传输确认后才可被 LM 使用；同内容复用 EC，失败不前向。
- [x] `serving`：逐段查看 SSE JSON，role/content/finish/usage/[DONE] 保持 FIFO；慢客户端增加队列，断连停止生成。
- [x] `fault`：区分逻辑块释放与在途物理任务确认；worker 故障终止所有请求，单请求取消保留另一请求。

### 配置与平台条件分支

- [x] `configuration`：命令分析器先分组配置，再检查头数/TP 与 Runner/投机方法组合；失败不生成请求路径。
- [x] `attention-backends`：逐项过滤两个 Dense Attention 候选，查看所有淘汰原因；没有候选时不生成可执行元数据。
- [x] `adaptive-spec`：条件置信度连乘形成存活概率；按教学成本曲线选择跨请求预算并保留每请求前缀。
- [x] `platform`：选择平台查看 CustomOp 基类方法委托；缺少 native 实现时保持错误，不标为成功执行。
- [x] `compatibility`：切换组合逐项列出触发条件、冲突理由与源码；只承诺已检查规则的结果。

### 模型与接入边界

- [x] `mla`：将 latent/RoPE 表示、Top-k 稀疏索引和 F/S 跨层复用拆开；S 层不重新计算索引。
- [x] `speculators`：按同一 token 位置 stack 辅助层，展示 next-token 样本与导出结构；层错位时禁止导出。
- [x] `elastic`：所有逻辑专家的目标权重与通信组屏障确认后才切拓扑；失败保留原 epoch/world。
- [x] `long-context`：成对旋转数值与向量范数可检查；窗口改变可访问历史，超 max_len 时阻止生成缓存。
- [x] `diffusion`：随机 token 画布逐轮更新候选、熵筛选与稳定状态；收敛帧不提交，下一帧只提交有效长度。
- [x] `invariance`：以 Math.fround 比较 FP32 逐加归约，观察部分和、临界 logits 和 argmax；统一顺序后结果一致。
- [x] `plugins`：对照 General 与 Endpoint 的默认白名单规则；各进程注册独立，加载失败不会进入 registry。
- [x] `connectors`：逐层等待 KV 加载完成再消费；发送/接收完成集合分别确认后才能释放生产侧资源。
- [x] `rust`：观察 Rust Add/Abort 类型、请求字段与输出结束枚举；ZMQ/MessagePack 与 gRPC 边界分别说明。

### 已有状态专题深化

- [x] `scheduler`：调度微事件可暂停，轮次按钮跳转结算帧。
- [x] `chunked`：同工作负载同步轮次对照，停滞不作为更快结果。
- [x] `paged`：逐 token 的读写地址链与 slot 映射。
- [x] `prefix`：整块查询、绑定增引用、尾部 KV 与末尾 logits。
- [x] `speculative`：逐位置检验、首拒绝截断、恢复与提交分开。
- [x] `tp`：逐列局部部分和、归并贡献与完整矩阵对照。
- [x] `pp`：microbatch 身份、跨时隙交接、填充 / 稳态 / 排空。
- [x] `moe`：逐 token 分发、原 rank 与 Top-2 加权返回。
- [x] `structured`：语法状态、允许 / 排除集合和合法字符串参数。
- [x] `offload`：GPU / CPU / 外部容量、淘汰、回载与完成依赖。
- [x] `disagg`：同一请求的单实例 / 分离部署依赖对照。

验收：169 项 Node 回归通过；页面交互、窄屏与控制台结果记录在 CHANGELOG。仍需保持的边界包括模型训练与真实权重、完整 Attention 后端条件、实际硬件数值路径、异步网络和外部库；各窗口已就地标注。后续扩展须选择具体模型与后端，再定义新的可验证状态，不能据此宣称已无改进空间。

初始盘点的结构性原因与本轮改动：

- [`renderers.mjs`](../src/renderers.mjs) 的 `scene()` 对未实现专用场景的专题调用 `flow()`；后者主要显示节点、文字和进度标记。
- [`engine.mjs`](../src/engine.mjs) 的 `buildTrace()` 对未接入教学引擎的专题直接映射 `lesson.steps`，没有独立的运行状态。
- [`app.mjs`](../src/app.mjs) 的播放循环只负责递增帧位置。增加播放速度或 CSS 效果不会自动补出请求、张量、缓存或依赖关系。
- 本轮页面根据实现区分“执行观察窗”“流程概览”“机制图解”，[`learning-view.mjs`](../src/learning-view.mjs) 的徽标同步区分“可推演实验”“流程概览”“专用图解”。

LoRA / EPLB 已增加混合请求数值与布局迁移，媒体对齐、流式协议、工具 parser 和故障传播均有独立记录。不同模型与平台的范围在窗口内明确标注；教学机制仍不等于完整生产实现。

## 第一轮：已补齐 8 个基础状态观察窗

按以下顺序完成：生命周期 → Runner → 抢占 / 取消 → 优先级 → 异步 → 混合 KV → Beam → 动态 K。统一支持参数重算、回放、事件帧与讲解环节映射、源码跳转及断点恢复。

落地范围：抢占和优先级观察窗使用固定三请求负载，完整请求编辑仍在连续批处理专题；异步提供 CPU / GPU / 结果三泳道，暂不模拟真实 IPC 和同一请求跨轮依赖；混合 KV 的状态空间对照是示例递推，暂不包含 checkpoint。这些扩展仍可继续深入，不应把基础观察窗视为生产实现的完整复现。

下表保留初始建议，作为后续深化的参考。优先级依据是学习主线、明确可观察状态和现有引擎复用；工作量为相对估计，不是工时承诺。

| 顺序 | 专题                 | 建议的观察窗                                                                                  | 学习者可改变的输入                     | 工作量 |
| ---: | -------------------- | --------------------------------------------------------------------------------------------- | -------------------------------------- | ------ |
|    1 | 一个请求的一生       | 同一请求依次进入前端、队列、GPU、采样和流式输出；token 与 KV 块随轮次变化，结束后回收         | prompt 长度、输出上限、停止条件        | 中     |
|    2 | Model Runner V1 / V2 | 请求 A/B/C 的持久行、当轮顺序、gather 索引与 `input_ids` / `positions` / block table 并排变化 | 新增 / 完成请求、本轮请求排序、V1 / V2 | 中     |
|    3 | 抢占、重算与取消     | 显存不足 → 选中受害请求 → 释放可释放块 → 重算 KV → 继续生成；取消走独立终止路径               | 块容量、取消时机、请求长度             | 中     |

|    6 | 滑动窗口与混合 KV    | token 向前推进时，窗口滑动、旧块跳过或释放；完整注意力和不同缓存组并排对照                    | 窗口长度、block 大小、层类型           | 大     |
|    7 | Beam Search 与多样本 | 候选树逐层展开，显示累计分数、保留分支和被剪枝分支；对比独立多样本                            | beam 宽度、候选分数、停止条件          | 中     |
|    8 | 动态草稿长度         | 并发数跨越配置区间时，K 与草稿位置数量同步变化；K=0 展示关闭草稿的路径                        | batch size、区间表                     | 小     |

复用与边界：

- 请求生命周期可组合现有调度、KV 和采样教学组件，不需要运行真实 tokenizer 或模型；示例 token 必须标明是教学输入。
- 抢占已有 [`engines/scheduler.mjs`](../src/engines/scheduler.mjs) 的块释放、历史重算和输出保留逻辑可复用。取消事件、在途资源与优先级还要增加状态，不能只给现有图改标题。
- Runner V2 的持久请求行与当轮 gather 可直接对照固定版本的 `docs/design/model_runner_v2.md`；不能把两个 Runner 的布局画成完全相同。
- 异步调度使用带依赖的教学时间线。只有满足完成条件后才允许消费结果，示例时间不作为硬件实测。
- 混合 KV 需区分 full attention、sliding window 和状态空间缓存；不能把所有层都表示成同一种 K/V token 数组。
- 动态草稿区间来自固定版本的配置规则；文档示例值不表示通用最优参数。

## 实施方式与验收标准

1. **先定义状态，再画动画。** 每个机制输出初态、事件、下一状态与可观察数值；动画、解释、指标和源码入口读取同一份执行记录。
2. **讲解步骤与播放帧分开。** 一个讲解步骤可包含多个微事件帧，通过 `stepIndex` 关联原有讲解、理解题和源码，避免增帧后跳错代码。
3. **复用三类场景。** 请求 / 资源状态用于生命周期、抢占、睡眠和故障；带依赖的时间线用于异步、DBO 和传输；张量 / 表格映射用于 Runner、Pooling、LoRA 和量化。
4. **保持对象身份。** 请求、token、物理块和专家使用稳定标识。现有 [`dom.mjs`](../src/dom.mjs) 已保留部分控件节点，可扩展稳定标识支持，再做位置和数值的过渡动画。
5. **参数必须改变结果。** 改窗口长度应改变可见历史，改优先级应在适用场景改变候选顺序，改 beam 宽度应改变保留分支，不能只修改说明文字。
6. **提供失败或边界场景。** 如没有 KV 空闲块、没有历史匹配、CUDA Graph 形状未命中、传输尚未完成、优先请求仍受资源限制。
7. **改善学习深度提示。** 入口与观察窗使用“可推演实验 / 专用图解 / 流程概览”标识，避免所有专题给人同样的动画深度预期。
8. **保留可控回放。** 暂停、单步、回退、重置与参数复现必须正确；减少动态效果偏好、键盘操作和窄屏均可使用。
9. **验证机制而非截图。** 检查块不重叠、资源守恒、依赖先后、停止后不继续生成、概率归一化等不变量，再验证页面和源码定位。

实施顺序已落实：基础流程 → 核心数值图 → 投机可编辑输入 → 服务协议 → 模型 / 平台分支 → 原有观察过程深化。保留无需 GPU、固定版本源码、离线运行的使用方式。
